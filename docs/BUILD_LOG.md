| 2026-10-27 | Leak fix for tool output that names no file (separate worktree). The bench's first finding, customer names printed by a failing test going to Contributor (8 canary violations in the Mint arms, 32 with rule learning), is closed with two deterministic mechanisms in the gateway: paths printed in the output or named by the command (tracebacks, `path:line`, pytest ids, compiler output, Windows paths, diff headers) are judged by the path rules with unreviewed meaning CONFIDENTIAL and are placed with `x-cm-root`, the call's cwd or the working directory in the system prompt; and in-memory keyed-hash fingerprints of sensitive text read earlier (names, identifiers, rare numbers; unreviewed sources count only names and identifiers; terms of cleared files and of the caller's own prompt are exempt) label later output that repeats it. The review queue is ordered by how many requests a path holds back. Bench result: 0 canary violations in arms 3-6, 37/37 accepted; arm 5 keeps e = 48.5% (52.2% before, 6.9 points of which were the leaking requests); arms 3 and 4 fall from about 20% to about 10%. Ablation arms and a static false-positive audit are in `bench/`. Known limit: names the gateway never saw read are not recognized. |
| 2026-10-29 | Billing mode. Checking the account's billing page found that use paid with promotional credits counts as non-paid under the Terms (§13.3), and every non-paid request may be used for training (§6), on Standard models too. `CM_BILLING=credits` (the default) therefore sends Meta only clean Contributor requests: what fails the Contributor test goes to a local model at `LOCAL_API_BASE` if one is configured and is otherwise held (403, lane `held`, recorded in the ledger), in the proxy and in MCP `delegate`. `paid` keeps the Standard lane. The ledger records the billing mode, local and held requests, and spend paid with credits. 8 tests, including a randomized check that on credits every request reaching the Meta host is a Contributor request with no planted secret. Existing tests and the bench pin `paid`. Rerunning the reference run gives byte-identical `results.json`, `tasks.csv`, `violations.csv` and `learning_curve.csv`. |
| 2026-10-30 | L9 dashboard (separate worktree): a Next.js page for the demo video showing the billing mode and why credits hold back or keep local what may not go to Contributor, spend against the all-Standard counterfactual, compute multiplier, contributable token share, cache hit rate, credits used, where every request went with its reason (lane mix, timeline, table), the masked context that left the machine with placeholders highlighted, the review queue with decisions made on the page, and the bench reference run (acceptance, e, compute multiplier, canary violations). | 2026-10-30 | Streaming and `/v1/responses` (separate worktree), on mock upstreams only. `stream: true` relays SSE: placeholders cut between deltas are held back and restored, per choice and per tool call, proved by randomized splits; provenance and origin are recorded from the assembled message when the stream finishes, with the same fingerprint as a non-streaming reply; usage is requested upstream and the ledger row is written however the stream ends (client disconnect, including over a real socket, upstream failure, upstream 4xx/5xx), with the upstream connection closed; lane, `held` and upstream errors come before the stream, later failures as SSE errors, cost as an SSE comment. `/v1/responses` translates into the same shared path and always uses chat completions upstream: `previous_response_id`, `conversation`, `prompt`, `background` and `item_reference` are refused, `store` is always false, a `function_call_output` without its call is refused, and reasoning or unknown model-generated items are never sent and keep the request off Contributor.
